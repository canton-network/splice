## 11255 briefing

What it is: when a test setup grows the BFT ordering topology (typically 1 -> 4 sequencers), submissions sent
around the switch get lost. There are three shapes:
- rejected send: `P2P connectivity is not ready` on the participant, within about 3 s after the switch;
- batch never ordered: a `LocalBatchCreated` just before the switch with no `Deliver` for its message ids;
- lost verdict: a sequencer blacklisted after a view change refuses a mediator's verdict.

A lost MediatorSynchronizerState signature leaves the joining SV waiting on `Mediator has been granted unlimited
traffic` until the 5 min init wait ends. If that happens in a setup step, the later suites of the shard fail too
(no reset; sv1 PartyToParticipant `TOPOLOGY_UNAUTHORIZED_TRANSACTION`).

Rate: on 2026-11-13, every post-merge main run from 10:30 to 16:45 UTC had a failed shard of this family (7 of 7).
The Canton bump to 3.7.4-snapshot.20261112 did not change it.

Fixes: splice#8356 (merged) disables blacklisting, but only in simtime environments; 11395 shows the lost-verdict
shape in a wall-clock suite after a host stall. Fix PR splice#8363 (one SV sequencer onboarding at a time in tests)
is open. `fixes/11255/` on this branch has the fix options and plans by the parent's assignee.

New hits: run the confirm grep for the shape (family B lists them by date), then close as a duplicate with a
one-line comment about that hit. Comment on the parent only if a hit changes the understanding of the issue.
