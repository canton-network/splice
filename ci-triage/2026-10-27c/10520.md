# 10520 - mainnet-Daml nightly: SV1 bootstrap fails INITIAL_ONBOARDING_ERROR, TOPOLOGY_SERIAL_MISMATCH (run 40064890060)

Verdict: new family, deterministic, every shard of every "Integration tests against mainnet Daml version" run since
2026-10-24 (the per-job issues 10521-10541, 10546-10567, 10572-10593, 10652-10670 are already closed as dups of 10520).
The nightly builds a PV 36 synchronizer (`protocol_version: "36"` in `.github/workflows/daml_compat_test.yml`). SV1
puts sv1Participant's identity transactions into the genesis state raw from the participant's Authorized store
(`getIdentityTransactions`), while it builds the mediator and sequencer ones with
`generateOnboardingTopologyTransactions(sv1Config.initialProtocolVersion)`. When sv1Participant then connects, its
onboarding outbox sends the same NamespaceDelegation and OwnerToKeyMapping (serial 1) with a different tx hash
(306eee... instead of the genesis 96687703...), the sequencer does not see them as duplicates, validates them as new
serial-1 transactions on top of the genesis serial 1, and rejects them: `SerialMismatch(expected = 2, actual = 1)`.
The regression window is 63fdd611de (10-23 nightly green) .. bbe721d221 (10-24 red): #7944 (Canton
3.7.0-snapshot.20261015 -> 20261022) and #7910 (stable PV 37, alpha-version-support removed). Production code in the
SV app; owner: #7910/#7944 authors (Julien), Pawel looked at it on 10-26.

- Run: https://github.com/canton-network/splice/actions/runs/40064890060 (schedule, workflow "Integration tests against

## Verdict

New family, real regression (not a flake), only for SV1 bootstrap of a synchronizer below the participant's default
protocol version: the mainnet-Daml nightly (PV 36) and `splice-localnet-compose.sh -p 36`; existing networks are not
affected (no genesis is built). Fix in the SV app: build sv1Participant's identity part of the genesis with
`participantAdminConnection.generateOnboardingTopologyTransactions(sv1Config.initialProtocolVersion)` like the mediator
and sequencer, so the hashes match what the outbox later sends. Not verified: which of #7944 / #7910 changed the
participant's stored representative (decisive check: rerun the 10-23 nightly sha with Canton 20261022 or compare
the 96687703/306eee bytes); the proposed fix is not compiled or run. No fix branch written (production change, owner).
