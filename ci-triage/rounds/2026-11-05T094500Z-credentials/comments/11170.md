Likely a race in the cluster reset, not a problem with the lock itself: two stacks are destroyed in parallel in the same namespace.

The reaper found the scratchnete lock too old and ran the reset, which destroys all Pulumi stacks in parallel (`cluster/pulumi/pulumiDown.ts`). In both failures (also #11196) the sv stack starts deleting namespace `sv` while the sv-runbook stack is still uninstalling its Helm releases there, and the uninstall then fails:

```
03:04:25.609 [organization/sv/sv.sv.scratche]- kubernetes:core/v1:Namespace: (delete)   [id=sv]
03:04:34.699 [organization/sv-runbook/sv-runbook.scratche]- kubernetes:helm.sh/v3:Release: (delete)   [id=sv/cluster-ingress-sv]
03:04:43.434 [organization/sv-runbook/sv-runbook.scratche] - error - error: uninstallation completed with 1 error(s): uninstall: Failed to purge the release: release: not found
03:04:46.412 Aborting after the wait time: organization/sv-runbook/sv-runbook.scratche - Aborting because of caught exception
```

The first failed operation aborts all others, so the `context canceled` / `client rate limiter Wait returned an error: context canceled` errors in the other stacks are a consequence. The log does not show that the namespace deletion removed the release record; the timing is the same in both runs (namespace delete 9 s and 8 s before the release delete).

Fix: destroy sv-runbook before the sv stacks in `pulumiDown.ts`, or treat "release: not found" during uninstall as already deleted.
