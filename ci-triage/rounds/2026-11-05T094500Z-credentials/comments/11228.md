Test flake, likely on the client side: the sv1 participant's admin API was up after 45 s, within the test's 60 s budget, but the test's next three polls still failed immediately.

Sv1BootstrapProtocolVersion36IntegrationTest creates its admin connections before the standalone Canton starts, then polls `GetId` on each node for 60 s in its first clue ("Canton nodes are running but have no identity"). Canton starts the sequencers, then the mediators, then the participants. The sv1 participant listened on 27102 from 14:17:51; the polls at 14:17:55, 14:18:00 and 14:18:05 failed within the same millisecond and never reached the participant (it logs no request):

```

14:17:07.347 Starting Canton version 3.7.2

14:18:06.278 Failed clue: Canton nodes are running but have no identity
```

Failing without a connection attempt fits gRPC's reconnect backoff on a channel that has failed since 14:17:06; the logs do not show the channel state, so this is not confirmed.

Fix (test only): create the admin connections after Canton is up, or use a fresh connection per poll, so the backoff from the 45 s of startup does not carry over. A longer budget alone would also have passed here, but only because the backoff ends eventually.
