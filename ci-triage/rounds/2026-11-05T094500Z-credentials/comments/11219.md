Product bug in the validator: ReconcileSequencerConnectionsTrigger ignores the configured sequencer trust threshold.

The test configures aliceValidator with svNames sv1-sv3 and threshold 2. The validator registered the synchronizer with threshold 2 at startup, but the trigger's first run used a synchronizer time 9 s behind (12:00:19), when sv2's sequencer was not yet available (availableAfter 12:00:25.39). It replaced the connections with sv1 and sv3 and threshold 1, then re-added sv2 a second later, still with threshold 1. (The test waits until all sequencers are available by the environment clock before starting alice; that does not cover the trigger reading at the lagging synchronizer time.)

```
12:00:27.493 Ensuring domain Synchronizer 'global' registered with config SynchronizerConnectionConfig(... SEQ::sv1 ... SEQ::sv2 ... SEQ::sv3 ... sequencer trust threshold = 2, ...
12:00:28.365 For synchronizer Synchronizer 'global' at time 2026-11-04T12:00:19.020727Z using Vector(... SEQ::sv1 ... SEQ::sv3 ...) from scan
12:00:28.381 modifying sequencers connections to SequencerConnections(connections = Map(Sequencer 'SEQ::sv1::1220bdb91509...' -> ..., Sequencer 'SEQ::sv3::12206fa6a3e7...' -> ...), sequencer trust threshold = 1, ...
12:00:29.728 For synchronizer Synchronizer 'global' at time 2026-11-04T12:00:29.543819Z using Vector(... SEQ::sv1 ... SEQ::sv2 ... SEQ::sv3 ...) from scan
12:00:29.735 modifying sequencers connections to SequencerConnections(connections = Map(Sequencer 'SEQ::sv1::1220bdb91509...' -> ..., Sequencer 'SEQ::sv2::12208562eae1...' -> ..., Sequencer 'SEQ::sv3::12206fa6a3e7...' -> ...), sequencer trust threshold = 1, ...
```

SynchronizerConnector uses `trustedSynchronizerConfig.threshold`, the trigger always uses `Thresholds.sequencerConnectionsSizeThreshold` (f+1, so 1 for 3 sequencers), and it only compares endpoint sets, so the wrong threshold is never corrected. Outside tests, any change of the trusted SVs' sequencers (e.g. a URL change) lowers a validator's configured threshold to f+1; whether a restart restores it is not checked.

Fix: use the same threshold and amplification in the trigger as in SynchronizerConnector, and also compare the threshold when deciding whether to modify. The test's sv2 URL change already exercises this path; asserting threshold 2 after it makes the test fail without the fix.
