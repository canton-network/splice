The mainnet Daml compatibility run executes TrafficBasedRewardsDryRunTimeBasedIntegrationTest although it needs splice-amulet 0.1.25: the `SpliceAmulet_0_1_25` tag added in canton-network/splice#8224 sits on the abstract base class `TrafficBasedRewardsTimeBasedIntegrationTestBase`, and our tag annotations are not `@Inherited`, so scalatest does not see it on the concrete classes.

sv1 then bootstraps the DSO with the new reward config field, which the mainnet AmuletConfig cannot hold, and the SV app fails to initialize:

```
05:31:32.688 WARN SV1Initializer | The operation 'bootstrapping DSO' failed with a non-retryable error, not retrying: ... COMMAND_PREPROCESSING_FAILED(8,2b1e16bc): An optional contract field ("extraFeaturedAssetActivityWeight") with a value of Some may not be dropped during downgra...
05:31:32.690 ERROR SV1Initializer | Gave up ensuring the DsoRules and AmuletRules are bootstrapped
05:31:32.697 ERROR SvApp | sv1 app initialization: Initialization failed
```

The run did exclude the tag (`-l org.lfdecentralizedtrust.splice.util.scalatesttags.SpliceAmulet_0_1_25`). Scalatest 3.2.19 reads class tags with `Class.getAnnotations`, which only returns a superclass annotation if it is `@Inherited`. This was the first nightly with #8224; the previous one passed. It will fail every night until fixed (TrafficBasedRewardsTimeBasedIntegrationTest has the same problem; it also ran in this run, in another shard, and failed there on an unrelated leftover environment first).

Fix: move the tag annotations to `TrafficBasedRewardsTimeBasedIntegrationTest` and `TrafficBasedRewardsDryRunTimeBasedIntegrationTest`, or mark the annotations in `apps/common/src/test/java/org/lfdecentralizedtrust/splice/util/scalatesttags/` as `@Inherited`.
