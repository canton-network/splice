Correction to the cause above: the test does not need splice-amulet 0.1.25 (#7627 only adapted a config constructor in it). It needs the network's active amulet version to be the latest one, which the mainnet Daml nightly breaks by design.

ProcessRewardsTrigger creates a provider's RewardCouponV2 hidden (`providerIsObserver = false`) only if the provider has not vetted the active amulet version. The test makes Alice unvetted by unvetting `DarResources.amulet.latest` on her participant. On main, latest is the active version, so her coupon is hidden as expected. In the nightly the active version is MainNet's 0.1.24, which Alice still has vetted, so her coupon is created visible and line 206 fails:

```
Vector() was empty (UnhideAndExpireRewardCouponV2TimeBasedIntegrationTest.scala:206)
```

The SV app logs every hidden coupon with `Providers with wrong vetting state for batch`: 0 lines in the nightly of 2026-11-04 (simtime (3), run 41776986892), 3 lines in a passing main run of the same test. A `SpliceAmulet_0_1_25` tag would only hide this until MainNet runs 0.1.25 and main has 0.1.26.

Fix: tag the suite `NoDamlCompatibilityCheck` instead of `SpliceAmulet_0_1_19`, so the nightly skips it. Making the test unvet the active version instead of `latest` would let it run in the nightly again; that is a larger change for the test owner.
