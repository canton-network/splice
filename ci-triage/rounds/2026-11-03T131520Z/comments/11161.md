Test flake in the shared frontend login helper, no product change needed.

SplitwellFrontendIntegrationTest (settle debts with a single party) on main be675a11dd, frontend-wall-clock-time (1), failed while logging bob in to the wallet after the splitwell transfer redirected to `/confirm-payment/<cid>`:

```
[frontend=bobSplitwell step=enter-payment-accept-verify] Could not find IdQuery(user-id-field) (FrontendIntegrationTest.scala:427)
```

Bob was still logged in to the wallet from test case 0. `FrontendLoginUtil.loginOnceConfirmedToBeAtUrl` checks once per attempt whether `#logout-button` is present (and logs out if so), then waits 3 s for the login form; its 5 s budget allows two attempts. The confirm-payment page needed 3.8 s after the click to load, so both logout checks ran before React had rendered anything:

```
12:26:43.923 0 <- [1,919,{"error":"no such element","message":"Unable to locate element: #logout\\-button", ...
12:26:47.022 WebDriverBiDiConnection <- {"type":"event","method":"browsingContext.domContentLoaded", ... http://localhost:3001/confirm-payment/00eb967...
12:26:47.113 0 <- [1,932,{"error":"no such element","message":"Unable to locate element: #logout\\-button", ...
12:26:50.118Z Failed clue: Waiting for login page to be ready
```

The helper then waited for `#user-id-field`, which a logged-in wallet never shows. The failure screenshot at 12:26:50.15 shows the wallet rendered as logged in (`Logout`, bob's balance). No console errors and no `disallowed MIME type` in the browser log. A 3.8 s load is normal for the wallet on the Vite dev server in CI (in another frontend run, 23 wallet page loads from navigate to DOMContentLoaded: median 3.1 s, max 4.7 s; splitwell pages 0.5 to 1.4 s), so the 5 s budget of the helper is only just above a normal load.

Not caused by the react-router 8 bump in this commit: the same shard passed on the next two main runs, which contain it.

Fix (test only): raise the budget of the login attempts in `loginOnceConfirmedToBeAtUrl` from 5 s to 15 s, so a slowly loading page gets further logout checks after it has rendered.
