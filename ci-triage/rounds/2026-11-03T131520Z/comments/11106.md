The ciperiodic deploy_sv_reonboard deployment fails to render the validator Helm chart since splice #8137 (Restrict allowed origins for the validator API without auth, merged 2026-10-30 09:28 UTC). This issue is the first failure; the later runs (#11137, #11142, #11151, #11171, #11183) are closed as duplicates.

The deployment fails with:

```
allowedOrigins must be set when disableAuth is true
```

#8137 added this check to `cluster/helm/splice-validator/templates/validator.yaml`:

```
{{- if .Values.disableAuth }}
{{- if not .Values.allowedOrigins }}
{{- fail "allowedOrigins must be set when disableAuth is true" }}
```

but changed nothing under `cluster/pulumi`. Pulumi still passes `disableAuth` to the validator chart for validator1 (`cluster/pulumi/common-validator/src/validator.ts`, `disableAuth: baseConfig.disableAuth || false`; per its config, disableAuth is only honoured for validator1) and never sets `allowedOrigins` on that chart, so a deployment that runs validator1 with `disableAuth: true`, as sv_reonboard does, can no longer be rendered. No fixture in `cluster/expected` uses `disableAuth: true`, so the Pulumi snapshot tests did not catch it. The splice commits deployed by this run (76e1efc724) and by #11137 (e4825eacda) both contain #8137.

Fix (Pulumi): when `disableAuth` is set, pass `allowedOrigins` to the validator chart (for validator1 the origins of its wallet and ANS UIs), and add a `cluster/expected` fixture with `disableAuth: true` so the combination is rendered in CI. Assigned to @OriolMunoz-da as the author of #8137.

Not checked: the sv_reonboard runs of 10-31 and 11-01 passed according to the earlier comments here, although main already contained #8137; which splice commit they deployed, or whether they rendered the validator1 chart at all, is in the CircleCI logs of those runs.
