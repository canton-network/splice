The test case `Grant, Update, Amend and Revoke Featured App Right` in `SvFrontendIntegrationTest` now needs splice-amulet 0.1.25, but it has no version tag, so the mainnet Daml nightly (splice-amulet 0.1.24, splice-dso-governance 0.1.30) runs it and fails on every run.

canton-network/splice#8062 made the test fill the new `appKind` and `opsParties` fields of the GrantFeaturedAppRight form. Against splice-amulet 0.1.24 the vote request is rejected:

```
05:25:05.860 HTTP POST /api/sv/v0/admin/sv/voterequest/create from (127.0.0.1:39084): Received entity data: {...\"tag\":\"SRARC_GrantFeaturedAppRight\",\"value\":{...\"activityWeight\":\"2.5\",\"appKind\":\"FAK_AssetMoving\",\"opsParties\":[...]}}}},...}
05:25:05.984 Request to http://localhost:5114/api/sv/v0/admin/sv/voterequest/create resulted in a gRPC StatusRuntimeException: INVALID_ARGUMENT: COMMAND_PREPROCESSING_FAILED(8,495aa838): An optional contract field (\"appKind\") with a value of Some may not be dropped during downgrading.
05:25:05.985 HTTP POST /api/sv/v0/admin/sv/voterequest/create from (127.0.0.1:39084): Responding with status code: 400 Bad Request, took 124 ms
```

sv1 is therefore never redirected to the governance page, and the check fails after 20 s (`None was empty 'Initiate Proposal' button`). The same shard passed on the regular post-merge CI at the same commit (latest packages), and in the previous mainnet Daml nightly before #8062.

Fix: tag the test case with `SpliceAmulet_0_1_25` (`taggedAs Tag("org.lfdecentralizedtrust.splice.util.scalatesttags.SpliceAmulet_0_1_25")`, as in `TokenStandardTransferIntegrationTest`). The Amend step (`SRARC_CreateFeaturedAppConfigUpdateInstruction`, added together with these fields) needs splice-dso-governance 0.1.31 as well, so it has not run against MainNet's packages yet either; the tag covers both.
