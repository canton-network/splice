Slow runner: the SV nodes of the `SvFrontendIntegrationTest` environment initialized 1.3x to 1.8x slower than on the day before, and sv3 was not done when the 5 min setup wait for it ran out. The other five suites fail because the failed setup skipped the decentralized namespace reset.

`waitForNodeInitialization` waits for the nodes one after the other, 5 min each, and checked sv3 first, so sv3 got 5 min from 7 s after its own start. sv3 was still progressing (it was onboarding its sequencer and mediator) when the wait ended:

```
18:06:16.521 sv3 app initialization: Starting initialization
18:11:14.317 Proposing participant PAR::sv3::12203308a4f3... be promoted to Submission rights for the DSO party, will wait for it to take effect.
18:11:23.123 Timeout while waiting for initialization of sv3
```

Compared with the same setup on this shard on 2026-11-10, which passed:

| | 2026-11-10 | this run |
|---|---|---|
| loading package signatures (CPU only) | 30 s | 57 s |
| sv1 init | 1m36s | 2m48s |
| sv2 init | 4m12s | 5m30s |
| sv4 init | 3m40s | 4m57s |
| sv3 init | 3m48s | not done after 5 min |

No Daml, DAR or Canton version change between the two commits; each SV still uploads 87 DARs, 22 of them repeats (#11299). The slowdown is in every phase, including the CPU-only signature loading, so it points at the runner rather than a commit.

The later suites all time out on sv1, whose DSO party allocation is rejected with `Not fully authorized`: a failure in the setup step skips the plugins that reset the decentralized namespace (no `has been reset` line in the whole shard), the same blast radius as earlier setup failures in the simtime shards.

Possible fixes:
- Give `EnvironmentDefinition.waitForNodeInitialization` one overall deadline for all nodes (for example 10 min) instead of 5 min per node, which leaves the first node checked with only 5 min from its start.
- Deduplicate the DAR upload list (#11299), about a quarter of the uploads.
- Run the namespace reset also when the setup fails, so one slow setup does not take down the rest of the shard.
