Recurred in CopyVotesIntegrationTest setup on main with canton 3.7.2, with the circuit-breaker symptom: the BFT step from 2 to 4 sequencers stalled ordering for about 14 s, and the validator's first traffic top-up submission outlived the test-only 5 s gRPC deadline.

```
12:22:20.135 globalSequencerSv1  Authenticated P2P nodes count (including this node) 2 is currently below strong quorum size 3, ...
12:22:23.450 splitwellValidator  SubmitAndWaitForTransaction ... failed with DEADLINE_EXCEEDED/CallOptions deadline exceeded after 4.999796767s
12:22:34.920 globalSequencerSv1  BFT ordering request at index 6 in output block (epochNumber=33, blockNumber=570) with message ID c83c8959-...
12:22:43.617 splitwellValidator  Circuit breaker high-priority-connection tripped after 20 failures. Attaching last failure ... SUBMISSION_ALREADY_IN_FLIGHT
```

Epoch 32 activated the 4-node ordering topology at 12:22:20 while sv1 had only 2 authenticated peers, and the newcomers sv3 and sv2 set up the epoch only at 12:22:27 and 12:22:31; every segment of the epoch needed a view change, so nothing was output before 12:22:34. The top-up submission sent at 12:22:18.450 was delivered back at 12:22:35 and completed at 12:22:43.603.

In between, `TopupMemberTrafficTrigger` resubmitted the same command id every second. The breaker counted the deadline plus 19 `SUBMISSION_ALREADY_IN_FLIGHT` rejections and tripped at 12:22:43.617, 14 ms after the original submission completed.

A test-only mitigation for this symptom: raise `setDefaultGrpcDeadlineForBuyExtraTraffic` in `ConfigTransforms` from 5 s to 30 s, as canton-network/splice#7909 did for the treasury deadline. This submission took 25.2 s, so 30 s would likely have covered it. The ordering stall itself needs the Canton-side fix.
