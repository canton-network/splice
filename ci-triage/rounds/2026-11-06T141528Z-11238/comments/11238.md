Test race: the test reads the participant's connected synchronizers once, while the validator app on the same participant is briefly reconnecting it to pick up a newly available sequencer. Splice needs a one-line test fix.

`connect to all domains during initialization` disconnects sv4's participant, restarts the sv4 SV app and then checks `list_connected()` once, with no `eventually`. The SV app did reconnect the participant (`Successfully re-connected to synchronizers List(Synchronizer 'global')` at 11:01:03.842). About 33 s later, sv4Validator's `ReconcileSequencerConnectionsTrigger` added sv2's sequencer (scan reports it `availableAfter` 11:01:36.484607, that is publish time plus the default 60 s sequencer availability delay) and applied the change with a disconnect and reconnect. The test's single read landed in that 56 ms gap and got `List()`:

```
11:01:36.956 sv4Validator: reconnect to the synchronizer Synchronizer 'global' for new sequencer configuration to take effect
11:01:36.967 sv4Participant: Disconnected from Synchronizer 'global'
11:01:37.010 test: Request ListConnectedSynchronizers() has succeeded for remote participant for `sv4``.
11:01:37.012 test: Failed clue: sv will connect to all domains during initialization.
11:01:37.023 sv4Participant: Connected to synchronizer and starting synchronisation: Synchronizer 'global'
```

The check ran that late because the restarted SV app waits for its domain store, which polls connected synchronizers every 30 s and first polled 94 ms before the reconnect finished; `startSync()` returned only at 11:01:37. That put the read into the window in which sv4Validator adds the newly available sequencers of sv2, sv4 and sv3 (`availableAfter` 11:01:36.5, 11:01:37.9, 11:01:54.9). The gap per reconnect is short (56 ms here), so the test fails only rarely. The same assertion failed once before, in #5051 (2025-07, closed without analysis).

Fix: in `SvInitializationIntegrationTest.scala`, wrap the `inside(sv4Backend.participantClient.synchronizers.list_connected()) { case Seq(...) => ... }` after `sv4Backend.startSync()` in `eventually()`.
