## 2. ciperiodic is the only CI cluster that bootstraps its synchronizer at PV 36

```
git -C .claude/worktrees/cni grep -n "protocol-version\|PROTOCOL_VERSION" FETCH_HEAD -- cluster/deployment ':!*config.resolved.yaml'
```
```
cluster/deployment/ciperiodic/sv.yaml:14:    - name: ADDITIONAL_CONFIG_PROTOCOL_VERSION
cluster/deployment/ciperiodic/sv.yaml:16:        canton.sv-apps.sv.local-synchronizer-nodes.current.protocol-version = 36
```

(the override carries `# TODO(#7542) Remove this overwrite again`; cni main 1ef4be0, file last changed 10-16). The SV
app default is PV 37 since #7756 (10-20), so every other cluster bootstraps at 37. The LSU trigger
(`.circleci/triggers/enabled/ciperiodic-lsu-operator.json`) upgrades to `"lsu-protocol-upgrade-version": "36"`.

10520 shows that since #7944/#7910 an SV1 bootstrap at PV 36 fails deterministically: SV1Initializer puts
sv1Participant's identity transactions into the genesis raw from the participant's store, the participant's outbox later
sends the PV 36 form with another hash, and the sequencer rejects it with TOPOLOGY_SERIAL_MISMATCH, so sv-1 exits with
INITIAL_ONBOARDING_ERROR. The ciperiodic workflows that reset and redeploy the cluster (non_devnet, sv_reonboard,
lsu_operator base deploy, deploy_upgrade) would all stop at that point.
