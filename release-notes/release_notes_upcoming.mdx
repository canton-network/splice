## Upcoming for next patch release:

{/* Add all release notes in this section */}

  - Scan App

    - The following request fields now have a `maxItems` bound of 1000; requests exceeding it are rejected with 400:

      - `/v0/open-and-issuing-mining-rounds`: `cached_open_mining_round_contract_ids`, `cached_issuing_round_contract_ids`
      - `/v2/state/acs`: `party_ids`, `templates`
      - `/v2/holdings/state`: `owner_party_ids`
      - `/v0/holdings/summary`, `/v1/holdings/summary`: `owner_party_ids`
      - `/v0/voterequest`: `vote_request_contract_ids`

  - SV App

    - The following request fields now have a `maxItems` bound of 1000; requests exceeding it are rejected with 400:

      - `/v0/admin/sv/voterequest`: `vote_request_contract_ids`

    - Joining SVs now download the DSO party ACS and sequencer onboarding snapshots from their sponsor
      as files instead of receiving them in memory. This supports large snapshots and resumable downloads.
      SVs that restrict which endpoints other SVs can reach must allow the new
      `/api/sv/v0/onboard/sv/party-migration/prepare`, `/api/sv/v0/onboard/sv/sequencer/prepare` and
      `/api/sv/v0/onboard/sv/download/*` paths to sponsor new SVs;
      allowlists generated from their `x-external-audience: svs` annotation include them automatically.
      Sponsoring SVs must upgrade before onboarding SVs on this version.
      See "Configure storage for SV onboarding snapshots" in the SV operations docs for disk usage and configuration.
