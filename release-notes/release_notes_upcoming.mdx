## Upcoming for next patch release:

{/* Add all release notes in this section */}

  - Scan App

    - `/v0/events` responses now include two new per-event fields:

      - `asset_activity_records`: asset-side activity records. Always present; empty records when there's no asset activity.
      - `submitting_app_provider`: the submitting app provider party identifier when the submitter is a featured-app. Omitted from JSON when absent.

    - `/v0/reward-accounting/.../activity-totals` responses include five new required fields describing the app- and asset-side split of featured-app rewards:

      - `total_asset_activity_weight`: total asset-activity weight for the round.
      - `total_app_reward_from_app_activity`: app-source portion of the featured-app minting allowance.
      - `total_app_reward_from_asset_activity`: asset-source portion of the featured-app minting allowance.
      - `issuance_per_featured_app_activity`: CC rewarded per CC of featured app-activity coupon issued this round.
      - `issuance_per_featured_asset_activity`: ratio of Amulet minted per Amulet burned for asset activity.

      `total_app_reward_minting_allowance` now carries the combined app + asset allocation.

    - The following request fields now have a `maxItems` bound of 1000; requests exceeding it are rejected with 400:

      - `/v0/open-and-issuing-mining-rounds`: `cached_open_mining_round_contract_ids`, `cached_issuing_round_contract_ids`
      - `/v2/state/acs`: `party_ids`, `templates`
      - `/v2/holdings/state`: `owner_party_ids`
      - `/v0/holdings/summary`, `/v1/holdings/summary`: `owner_party_ids`
      - `/v0/voterequest`: `vote_request_contract_ids`
      - `/v0/validators/validator-faucets`: `validator_ids`

  - SV App

    - The following request fields now have a `maxItems` bound of 1000; requests exceeding it are rejected with 400:

      - `/v0/admin/sv/voterequest`: `vote_request_contract_ids`
