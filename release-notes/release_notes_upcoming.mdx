## Upcoming for next patch release:

{/* Add all release notes in this section */}

  - SV App

    - Joining SVs now download the DSO party ACS from their sponsor as a file instead of receiving it in memory,
      so onboarding works with large snapshots. SVs that restrict SV app ingress must allow other SVs to reach
      the new `/v0/onboard/sv/party-migration/prepare` and `/v0/onboard/sv/download/{id}` endpoints.

  - Deployment

    - SV onboarding snapshots are kept in `canton.sv-apps.sv.onboarding-snapshots.directory`, a new required setting
      that must point to persistent storage. The SV Helm chart now always creates a dedicated 35 GiB
      `onboardingSnapshotsPvc` for it, mounted at `/onboarding-snapshots`.

  - Scan App

    - Add the `compact_json_no_trailing_nulls` option to the `DamlValueEncoding` enum, used by the `daml_value_encoding`
      parameter of the update history and event history endpoints.
      It is the same as `compact_json`, except that trailing `null` fields of Daml records are omitted.
      With `compact_json`, values created before a Daml upgrade that appended optional fields can be
      returned with or without those fields (as `null`), depending on the version of the Scan app serving the request.
      `compact_json_no_trailing_nulls` returns the same JSON regardless of the Scan version.
      `compact_json` remains the default for now. Clients that compare responses across Scan instances should switch to
      the new encoding.
