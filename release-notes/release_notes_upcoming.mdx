## Upcoming for next patch release:

{/* Add all release notes in this section */}

  - Scan App

    - `/v0/events` responses now include two new per-event fields:

      - `asset_activity_records`: asset-side activity records (CIP-104). Omitted from JSON when there is no asset activity.
      - `submitting_app_provider`: the submitting app provider party identifier when the submitter is a featured-app. Omitted from JSON when absent.

    - CIP-104 v1.1 populates four optional fields on `OpenMiningRoundSummary`:
      `optIssuancePerFeaturedAppRewardCoupon`, `optUnclaimedAppRewards`,
      `optIssuancePerFeaturedAssetRewardCoupon`, and
      `optTotalFeaturedAssetRewardCoupons`. The two `*Asset*` fields carry
      the asset-side issuance ratio and the total featured-asset reward
      coupons.

    - Explorer operators:

      Because featured-app and featured-asset activity now have separate
      issuance ratios, explorers should ingest the new `*Asset*` fields
      alongside the existing app-activity ones; explorers that only read the
      app-activity fields will under-report total app rewards minted.

    - changed `/v0/internal/reward-accounting-process/rounds/{round_number}/activity-totals` to include additional fields

  - SV App

    - Removed the remaining CometBFT support from the SV app and UI, including the
      `/v0/admin/domain/cometbft/{status,json-rpc,debug}` endpoints, the
      `splice_sv_cometbft_*` metrics and the CometBFT debug tab in the SV UI.

    - Added support for the CIP-104 v1.1 (TBAR) governance changes:

      - The amended activity record computation is only used for rounds opening at or after
        the time set for the switch-over key `cip-104/use-amended-calculation-after`
        in `svOperationsSwitchOverTimes` of the DSO rules configuration.
        SVs activate it with a "Set Decentralized Synchronizer Operations (DSO) Rules Configuration" vote.

      - The "Set Amulet Rules Configuration" vote request now supports setting the new
        Amulet configuration parameters `extraFeaturedAssetActivityWeight` (default `0.2`),
        `maxExtraFeaturedAssetActivityWeightPerAsset` (default `0.1`), and
        `dsoAppActivityWeight` (default `0.1`). Leave a parameter blank to use its default.

      - The "Feature Application" vote request now supports setting all featured app metadata:
        app category (basic featured app, featured asset-moving app, or featured asset),
        app operations parties, and app composition weight.

      - Added the vote request type "Update Featured Application Metadata (use with Splice 0.10.0 and later)"
        to change the metadata of an already featured app.
        Once the vote is accepted, SV app automation applies the change to the app's featured app right;
        if that does not happen before the vote request timeout, the change expires and is discarded.
        The older "Update Featured Application Metadata (use before Splice 0.10.0)" vote request type
        can only change the app composition weight, and will be removed in Splice 0.11.0.

      - The SV app rejects creating a vote request to feature an app or update its metadata if:

        - the provider is already featured (when featuring an app),
        - the app operations parties contain duplicates or the provider itself, or
        - one of the app operations parties is already the provider or an app operations party
          of another featured app.

        The SV UI already flags the first two conditions while filling in the form,
        and additionally warns if one of the app operations parties is used in another pending vote request.

  - Helm charts and Docker images

    - Removed the remaining CometBFT support including the cometbft helm
      charts, docker images and unused `splice-info` values.

  - Scan App

    - Added `POST /v0/reward-coupons-v2-disclosures`, which returns base64-encoded
    created event blobs for active `Splice.Amulet:RewardCouponV2` contracts (up to
    100 contract IDs per request) for use by external reward-sharing automation.

  - SV App

    - Joining SVs now download the DSO party ACS from their sponsor as a file instead of receiving it in memory.
      This supports large snapshots.
      The new `/v0/onboard/sv/party-migration/prepare` and `/v0/onboard/sv/download/{id}` endpoints are annotated
      with `x-external-audience: svs`, so SVs restricting SV app ingress must expose them.
      Sponsoring SVs must upgrade to this version before they can onboard SVs that run it.
      Both SVs store the snapshots in `canton.sv-apps.sv.onboarding-snapshots.directory`, which defaults to a
      temporary directory and should point to a volume with enough free space.
